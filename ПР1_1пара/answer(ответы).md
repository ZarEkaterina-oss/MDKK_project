# Ответы на вопросы

## 1. Какие три основные области работы с файлами в Git и чем они отличаются?

Рабочая папка — место, где находятся и изменяются файлы проекта.

Индекс — область подготовленных изменений, которые будут включены в следующий коммит.

Репозиторий — место, где Git хранит историю сохранённых коммитов.

## 2. Что происходит при выполнении команд git add, git commit, git push?

`git add` добавляет изменения в индекс.

`git commit` сохраняет подготовленные изменения в локальный репозиторий.

`git push` отправляет локальные коммиты в удалённый репозиторий на GitHub.

## 3. Почему важно писать информативные сообщения к коммитам?

Информативное сообщение показывает, какие изменения были сделаны. Это упрощает просмотр истории проекта и поиск нужных изменений.

## 4. Чем отличается git add имя_файла от git add .?

`git add имя_файла` добавляет только указанный файл.

`git add .` добавляет все обнаруженные изменения в текущей папке.

Первый вариант удобен, когда нужно добавить конкретный файл, второй — когда нужно подготовить все изменения проекта.

## 5. Что показывает команда git status?

`git status` показывает состояние рабочей папки и индекса.

С её помощью можно узнать, какие файлы изменены, какие добавлены в индекс, а какие ещё не подготовлены к коммиту.

## 6. Для чего нужна команда git remote add origin URL?

Команда связывает локальный репозиторий с удалённым репозиторием по указанному URL.

`origin` — стандартное имя удалённого репозитория.

## 7. Зачем нужен флаг -u в git push -u origin main?

Флаг `-u` устанавливает связь локальной ветки `main` с удалённой веткой `origin/main`.

После этого можно использовать более короткую команду `git push`.

## 8. Что такое ветка по умолчанию и какая создалась у вас?

Ветка по умолчанию — основная ветка, которая создаётся для работы с проектом.

В данном репозитории используется ветка `main`.

Это важно, потому что именно с этой веткой выполняется основная работа и отправка изменений на GitHub.

## 9. Как просмотреть историю коммитов?

Для просмотра истории используется команда:

`git log`

Она показывает коммиты, их идентификаторы, автора, дату и сообщение коммита.

## 10. Что произойдет, если изменить файл, но не выполнить git add перед git commit?

Изменение не попадёт в индекс и поэтому не будет включено в новый коммит.

Сначала необходимо выполнить `git add`, а затем `git commit`.
